# Scopearr 1.2.2

Fix recognition-rule rewrites on large libraries under CPU contention. The post-release Main CI for 1.2.1 failed when reprocessing 100,000 files, and a controlled run reproduced `context deadline exceeded` without an OOM. Files with cached media-server matches now undergo filename/API enrichment once instead of twice. Their existing tracks, video evidence and named-instance identities remain intact.

The atomic rewrite has a bounded five-minute budget, including an interruptible backup. Expired operations return HTTP 503 with a clear message; the previous rules and cached files remain unchanged. Normal query budgets remain unchanged. A separate repeated 100,000-file synchronization reproduced an OOM at 256 MiB, so the supported container default is now **512 MiB**. Compose, the Unraid template and CI/load tests use this budget; tests still disable swap and retain the full dataset and integrity checks. **Existing containers must manually change `--memory=256m` to `--memory=512m` and update `--memory-swap` to 512m where supported.** Keep the Go soft target at 64 MiB.

Container tests now report the failing phase, method, endpoint and HTTP error body, distinguish overall success from synchronization completion, and support controlled CPU limits during reprocessing. Release publication and stable promotion additionally require a successful push-triggered Main CI run for the exact release commit. Pending checks wait; failed or missing checks block publication.

No database migration is required. See [the post-release validation report](../VALIDATION-1.2.1.md) for the original failure and the correction. Version 1.2.1 tags and images remain unchanged.
