# Scopearr 1.4.5

Disk placement now lists every relevant folder and gives the same answer in the list, status filters and live report. Settings saves explain what changed, and service fields align across the app.

- **Several disks** means that a folder exists on two or more devices, including cache and other pools, even when a copy is empty or a move is blocked. The filter includes mover, ownership, conflict and other error results. Successfully moved entries leave this filter.
- **Empty folder** means that no file, link or special entry exists anywhere in its directory tree on any device. These folders appear even on one disk and cannot be selected or started. **Empty copies** means that files are on one array disk and the other devices contain only empty directory trees. Cleanup leaves the target untouched, including its empty subfolders and zero-byte media files.
- Files only on cache plus an empty array copy now show **Waiting for mover**, with no manual target, instead of disappearing or reporting insufficient space. A folder only on one pool stays **On one disk**. Links and special entries count as content and retain a warning; a move is blocked if one would otherwise be left on a source device.
- Normal media folders beginning with `#` or `@`, such as `movies/#amleben`, are detected. Reserved recycle/snapshot/system names stay excluded. Hidden folders are excluded unless an Arr entry points to that exact name. Only shares resolved from selected Radarr/Sonarr roots are scanned; unrelated shares stay untouched.
- The report loads **live counts** and refreshes with the list. Every number opens the corresponding filtered rows, using the same SQL predicates. The new **Several disks by result** table includes split folders, empty copies, empty folders, mover, spread seasons and errors. The **One disk** and **Empty folders** filters are separate; saved `ok` filters remain valid.
- **Settings → System → Log** shows its list count immediately after the title, using the same badge as library and tool headings. Settings saves name their areas and service instances and show field changes in details; credentials appear only as `changed`. No-op saves create no event. Custom tags, tag rules and presets have concrete save/delete events. Area arrays are translated in the viewer; text exports retain English names.
- MKVToolNix package channel and retention controls use equal half widths. Radarr/Sonarr synchronization and start-time controls align with server address and API key and stack on phones. Settings section titles retain the same row height with and without Save settings.

## Check on the Unraid host

For an exact top-level comparison, select **Grouping by series**, run a fresh scan and use the share folder shown in the report. The helper includes all mounted pools, excludes reserved system names and checks complete directory trees across devices; an empty copy does not count as an Empty folder. Season grouping also counts season rows.

```bash
curl -fsSLo /tmp/scopearr-placement-host-check.sh \
  https://raw.githubusercontent.com/Buffer379x/scopearr/v1.4.5/docs/scripts/placement-host-check.sh
bash /tmp/scopearr-placement-host-check.sh documentaries several
bash /tmp/scopearr-placement-host-check.sh shows empty
```

Each output line is one logical folder with its device count and device names. See the Unraid guide for explicit hidden Arr folders, alternate roots and read errors.

## Compatibility and rollback

The `share` and `devices` placement columns and covering indexes are additive. The SQLite schema version is unchanged; 1.4.4's explicit column lists can still read and write the database. There are no dependency updates and rollback to 1.4.4 has no restrictions. **Run a new disk-placement scan after updating or rolling back.** The update does not start a scan automatically. Keep the 512 MiB memory limit without additional swap.

See the [validation report](https://github.com/Buffer379x/scopearr/blob/v1.4.5/docs/VALIDATION-1.4.5.md), [Unraid guide](https://github.com/Buffer379x/scopearr/blob/v1.4.5/docs/UNRAID.md) and [style guide](https://github.com/Buffer379x/scopearr/blob/v1.4.5/docs/STYLEGUIDE.md).
