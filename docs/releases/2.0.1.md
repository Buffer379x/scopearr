# Scopearr 2.0.1

Scopearr 2.0.1 makes syncs of large libraries faster, lets a filter drawer that failed to load open on the next try, and gives the tag rules table room for its longest values.

- **Faster syncs.** A full sync now prepares the statements it writes for every file once per sync, for custom tags, audio languages, search and years, instead of once per file. In the 100,000-file load test, a replacing sync of 20,000 movies took 8.2 s instead of 21.3 s, and one of 80,000 episodes took 35.2 s instead of 70.6 s. The stored data and the database schema are unchanged.
- **Filter drawers load again after a failure.** If a Filters drawer (Movies, TV series, Muxing, Disk placement, Files & permissions, the event log) could not be loaded, for example during a short network outage, the next attempt loads it from a fresh address. Older Chromium-based browsers had kept the failure until the page was reloaded. Safari keeps its previous behavior.
- **Tag rules columns fit their values.** Attribute, Match type and Mode are slightly wider and Result slightly narrower, so no value is cut by a pixel under other font metrics, for example the Spanish “Códec / codificador”. The table still fits without scrolling at 1440 px in every interface language.

The database schema stays at 18, and no settings or stored values were added. Rollback to 2.0.0 or 1.7.0 works on the same data.

Container: `ghcr.io/buffer379x/scopearr:2.0.1` (also promoted to `stable` after release checks).

See the [validation report](https://github.com/Buffer379x/scopearr/blob/main/docs/VALIDATION-2.0.1.md).
