# Scopearr 2.0.0

Work in progress on branch `release/2.0.0`: a redesigned interface that keeps every 1.7.0 workflow. Not released.

- Pages, filters and settings now have shareable URLs and work with the browser's Back and Forward.
- A new frame around the pages: a floating sidebar with Library, Tools and System (expanded from 1600 px, otherwise a narrow rail whose groups open beside it; on phones a drawer behind More), an accent band with the topbar and the page title, and a tab bar on phones (Dashboard, Movies, TV series, Tools, More). The settings areas are entries of the sidebar's Settings group; the breadcrumbs name the shown area. The sidebar remembers its mode and open groups, and theme and band style apply before the first screen, sign-in included, all in this browser only (`scopearr-sidebar`, `scopearr-sidebar-groups`, `scopearr-band`; 1.7.0 ignores them). Every entry is a real link, so Ctrl/Cmd-click opens a new tab. The pages themselves keep their 1.7.0 look on a sheet until they are redesigned.
- The frame's overlays: quick search (⌘K or Ctrl+K, or the magnifier in the topbar) finds pages by their names and movies and TV series by their titles, and opens the page or the library filtered by the title. The bell counts the open jobs of the tools; it opens a list of the tools with open jobs and, loaded only then, up to three running, waiting or failed jobs of each, with a link to the tool and Show in log for failed jobs. The sync display (the sidebar's card, the topbar's chip in the rail, the drawer's row on phones) opens a list of the enabled instances, each with its last sync and its own Sync now (Match now for a media server).
- The files API takes an optional `limit` (1 to 1000) as the page size of that one request; quick search asks for 6 titles. Without it the configured page size applies as before; an empty or invalid value returns 400 with the page-size message. 1.7.0 ignores the parameter.
- A new app icon: a mint to teal squircle with the magnifier and funnel, now without the film-strip dots, from one SVG master (`web/public/icon.svg`) for the favicons, the Apple touch icon (now 180 px) and the Unraid icon. Favicons and the Unraid template icon URL use the new cache key `?v=2.0.0`. The template's icon URL points to `main`, so Unraid shows the new icon only after 2.0.0 is merged there, and then also for installations that stay on 1.7.0 or go back to it. Existing containers keep their stored icon URL; see [Unraid installation](../UNRAID.md).
- Sign-in, setup and the loading screen in the new design: the app icon on the accent band, the form in a centered card with the interface language in its head, and a toggle that shows and hides the password. Every 1.7.0 step stays: the setup code and its hints, the demo's prefilled credentials, the session-expired notice and the error messages. The loading screen holds the icon where sign-in shows it, so nothing jumps when the page appears.
- SDR from explicit measurements: MediaInfo BT.709 without an HDR format and the Emby/Jellyfin range type SDR. SDR never appears together with an HDR profile; SDR measured against a filename profile shows as a metadata disagreement. The first 2.0.0 start makes one backup and refreshes saved details from the database without reading media files, so existing MediaInfo results gain SDR; media-server values follow the next sync. With HDR tag synchronization active, Radarr/Sonarr receive SDR tags, and those titles lose the `hdr-unknown` placeholder (a series keeps it while one of its episode files has no HDR value). After a downgrade to 1.7.0 and a return to 2.0.0, SDR derived from MediaInfo returns only with the next sync, MediaInfo read or rule change if 1.7.0 rewrote the files in between: the one-time refresh has already run.
- New default tag rules `HDR / SDR`, `Channels / 1.0` and `Channels / 6.1` recognize these filename tokens. The first start adds them once, together with the refresh above in a single backup and reprocessing; an equivalent rule of your own (also a disabled one) is kept instead, and a default you delete later stays deleted. At the 256-rule limit a rule is skipped with an event-log warning. With HDR or channel tag synchronization active, Radarr/Sonarr receive the new SDR, 1.0 and 6.1 tags after that first refresh; titles tagged SDR lose `hdr-unknown`.
- Audio track combinations in the files API: `track=<language>|<codec>|<channels>` finds files where one audio track has, for example, German and DTS-HD MA together, instead of German on one track and DTS-HD MA on another. It works for the file list, CSV export, custom-tag selection and saved presets, with `trackOp` for all/not/not-all. It uses measured tracks (MediaInfo, Emby/Jellyfin), so files without them never match positively. In the libraries the filter drawer offers it, and a track chip filters by its own track. After a downgrade to 1.7.0 a preset saved with a track combination ignores it and shows more matches, without an error. 1.7.0 also ignores the combination when comparing presets, so it may report a new preset as a duplicate of a 2.0.0 preset that differs only in it.
- Start-up no longer stops on display settings from a newer version: an unknown interface theme, dashboard widget, file-list column, Info action, or disk placement or file check column falls back to the default with one event-log warning per value. The correction stays in memory and the stored settings are unchanged until you save them; saving still rejects unknown values. Damaged settings and other invalid values still stop the start as before.
- Movies and TV series in the new design: the results card starts on the accent band and holds the search, the preset choice and a Filters button with the number of active filters in its head, the active filters as removable chips below it with the page tools (mark for muxing, remove the mux marking, set tags, all columns, save and delete a preset, CSV export), then the table and the pages. The filters open in a drawer on the right and apply only with Apply, which shows how many files match while you choose; Reset clears the drawer, closing it discards the choice. The search, a preset, a chip, Reset filters and the instance still apply at once. With more than one enabled instance, the page header offers All and each instance. A library that is not set up shows its setup notice first. When the active filters match no preset, the preset choice shows “Custom selection” instead of “All files”; an instance alone is no filter, so it shows “All files” and counts no filter, as in 1.7.0, and a preset still matches on an instance. The Audio tracks column shows each audio track as a chip with its language, codec and channels, up to two per row with the others behind `+n`; a chip's menu filters by its language, its codec or its channels, or by its language with its codec on the same track (a track combination, as in the drawer). On phones every row becomes a card with all its visible columns under a sort bar, and on wider screens the table header stays below the topbar while the table fits the card. Notifications stay top right but start below the card head and the page header's actions instead of covering the search, the Filters button, the instance choice or Retry. Every 1.7.0 filter, operator, state filter, preset, column, info icon, selection action and export stays.
- Settings → Display offers row density (Comfortable, or Compact for more rows at once) and stacked audio tracks (every track on its own line). Both apply to the libraries after Save settings and are stored in this browser only (`scopearr-density`, `scopearr-tracks-stacked`), never as a server setting, so 1.7.0 ignores them; while browser storage is blocked a saved choice holds until the page is loaded again.
- The dashboard in the new design: the four key figures (Movies, TV series, Episodes and Media files) start on the accent band and each opens its library; a row with Incomplete metadata (its Show opens the incomplete files), Media server matching as a bar and its four groups with help, and Storage as a ring with the used share, the legend and the storage areas; then the distributions of the chosen scope, each value with its count, its share and a bar, opening the filtered library. Every card has its size from the start, so nothing moves while the dashboard loads; More shows every value of a distribution and only lengthens its own card. The widget settings still choose and order the distributions; Storage sits in the row above them. Every 1.7.0 figure, filter link, help text, storage area and color stays; the stacked 1.7.0 distribution bars are replaced by one bar per value, in the accent color (user tag colors color the tag).
- Muxing in the new design: the page header with the open jobs and Show in log, four key figures (Open, Running, Failed, Successful) that filter the list by a press and reset it by a second, the MKVToolNix setup notice when it is missing, then the jobs card with the search, the presets and a Filters button that opens the status filter in a drawer (applied with Apply, with the number of matching jobs while you choose). The chips row holds the active filters and the page tools: Start selected and Remove mux marking count what they act on, Start all and Remove completed, save and delete a preset and the help. Every row has its options and terminal, a status button that opens the checks, its progress, and Start (or Retry) beside Cancel, Delete or Remove; Start is always in its place and locked while the job cannot start, so no button moves while a job runs. The page header's open count and the Open figure count the same jobs. On phones every row becomes a card with Details instead of the row actions. Every 1.7.0 filter, preset, sort, selection rule, question, action and dialog stays.
- Disk placement in the new design: the page header with the open items, Scan report (with its dot when the last scan left notices) and Scan, then a row of disk cards with every array disk and pool, its used share and free space, “Pool (not a target)”, the Target mark of the moves on the shown page and Standby while Unraid reports a disk spun down. The items card has the search, the presets and a Filters button that opens Shares, Status and Kind in a drawer (applied with Apply, with the number of matching items while you choose); a running scan or move shows in its hint line. The chips row holds the active filters and the page tools: Start selected counts the selection, Start all, Cancel (always in its place, locked without moves) and Remove completed, save and delete a preset, Export CSV and the help. Every row has Details and Terminal, its disks and target, a status button that opens the checks (a move waiting for the mover or a parity operation says so), its progress, and Start beside Remove in the Actions column (formerly Remove); Start is always in its place and locked while the item cannot start. When the page is not ready, its reason and Open settings stand in the card. On phones every row becomes a card with Details and Remove. Every 1.7.0 filter, preset, sort, selection rule, question, action, report and dialog stays.
- Tool page fixes: beside an expanded sidebar at 740 to 899 px the 1.7.0 filter row puts the search on a line of its own instead of reaching past the page, and the tool tables measure their headers again when the interface font arrives late, so the columns fit their headers.
- Fixes two 1.7.0 display errors: file details name audio languages in the interface language (“German, English” instead of “Deutsch, Englisch”) in the evidence table, conflicts and the source menu, and the sign-in and setup footer keeps the space after the version (“2.0.0 · For your own server”). Stored language values and tag rules are unchanged.

Development safeguards:

- Downgrade check to 1.7.0, confirming the database and settings written by 2.0.0 remain usable by the previous release. A second, demo-mode scenario lets 1.7.0 rewrite all demo files through the audio track index triggers: the new default rules stay unchanged and appear once, 1.7.0 ignores a track filter and a preset saved with it without an error, and back on 2.0.0 the filter and the preset return the same files and the index equals a fresh rebuild.
- Playwright layout invariants that keep navigation, filters and dialogs steady.
- Internal restructuring of the web interface into shell, data provider and pages; no visible change.
