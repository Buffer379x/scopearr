# Scopearr 2.0.0

Work in progress on branch `release/2.0.0`: a redesigned interface that keeps every 1.7.0 workflow. Not released.

- Pages, filters and settings now have shareable URLs and work with the browser's Back and Forward.
- SDR from explicit measurements: MediaInfo BT.709 without an HDR format and the Emby/Jellyfin range type SDR. SDR never appears together with an HDR profile; SDR measured against a filename profile shows as a metadata disagreement. The first 2.0.0 start makes one backup and refreshes saved details from the database without reading media files, so existing MediaInfo results gain SDR; media-server values follow the next sync. With HDR tag synchronization active, Radarr/Sonarr receive SDR tags.
- New default tag rules `HDR / SDR`, `Channels / 1.0` and `Channels / 6.1` recognize these filename tokens. The first start adds them once, together with the refresh above in a single backup and reprocessing; an equivalent rule of your own (also a disabled one) is kept instead, and a default you delete later stays deleted. At the 256-rule limit a rule is skipped with an event-log warning. With HDR or channel tag synchronization active, Radarr/Sonarr receive the new SDR, 1.0 and 6.1 tags after that first refresh.
- Audio track combinations in the files API: `track=<language>|<codec>|<channels>` finds files where one audio track has, for example, German and DTS-HD MA together, instead of German on one track and DTS-HD MA on another. It works for the file list, CSV export, custom-tag selection and saved presets, with `trackOp` for all/not/not-all. It uses measured tracks (MediaInfo, Emby/Jellyfin), so files without them never match positively. The interface for it follows in a later 2.0.0 step. After a downgrade to 1.7.0 a preset saved with a track combination ignores it and shows more matches, without an error.
- Start-up no longer stops on display settings from a newer version: an unknown interface theme, dashboard widget, file-list column, Info action, or disk placement or file check column falls back to the default with one event-log warning per value. The correction stays in memory and the stored settings are unchanged until you save them; saving still rejects unknown values. Damaged settings and other invalid values still stop the start as before.

Development safeguards:

- Downgrade check to 1.7.0, confirming the database and settings written by 2.0.0 remain usable by the previous release.
- Playwright layout invariants that keep navigation, filters and dialogs steady.
- Internal restructuring of the web interface into shell, data provider and pages; no visible change.
