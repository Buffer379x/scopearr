# Scopearr 1.1.1

- Refresh technical tags managed by Scopearr when a movie or episode file changes in **Keep and only add** mode, including background webhook and scheduled synchronizations. Remove earlier values and unknown placeholders once the current file supplies their replacements, without a confirmation dialog or paused tag job.
- Preserve unrelated manual/foreign tags, disabled groups kept by policy, imported external tags and auto-tag-rule protection. Radarr/Sonarr retain tags while no file is cached; Sonarr removes a value only when no episode file still produces it. Preexisting Radarr/Sonarr assignments matching desired technical values become managed on reconciliation and are subsequently refreshed too.
- Apply the same refresh to Emby/Jellyfin tags that Scopearr actually added. Preexisting item tags remain preserved, even if they matched an earlier technical value. Custom-tag and Overwrite behavior remain unchanged.
- Queue a one-time tag reconciliation for instances using Keep and only add, so accumulated stale managed values are cleaned after upgrading.

Validation covers full and targeted Radarr reconciliation, Sonarr episode unions, unknown placeholders, kept groups, foreign assignments, empty snapshots, unmanaged definitions, Emby/Jellyfin ownership and the one-time startup step. Frontend tests/build, version consistency and Go race/vet checks are required before release; the approved release workflow additionally checks image security, both architectures and large-library operation.

No database schema migration is required; a one-time tag reconciliation is queued for instances using Keep and only add. Back up Appdata before upgrading. Rolling back to 1.1.0 does not restore upstream tags already removed by 1.1.1; 1.1.0 would accumulate subsequent technical values again. Unraid updates remain operator-managed.
