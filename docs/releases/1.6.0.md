# Scopearr 1.6.0

Scopearr adds optional MediaInfo inspection, manual choices for metadata evidence and custom-tag creation in the tag dialog. Unraid renames keep each file on its physical device, with a check for metadata written elsewhere during the service refresh.

- **Read a file with MediaInfo.** Add MediaInfo under Settings → Services, install its signed package and configure the shared path mappings. File & metadata gains Overview and MediaInfo tabs. Read file stores compact normalized metadata and track details; reads are explicit, limited to one file at a time and bounded by a 120-second timeout and 4 MiB command-output limit. Syncs, webhooks and mux jobs do not start reads. MediaInfo and MKVToolNix share the package installer and path-mapping components, while retaining separate package trees and settings. MediaInfo installation requires at least 150 MB free Appdata space.
- **Choose the evidence source to use.** The Used cell offers available filename, Radarr/Sonarr, media-server and MediaInfo values. Selecting one stores a field-specific confirmation with its source, saved value and date. That field's disagreement and rule warnings are suppressed; other fields retain their findings. Automatic removes the confirmation. A Confirmed filter finds active choices. Confirmations survive sync rebuilds while the service, file ID and size still match.
- **Compare against the best available measurement.** Known filename values retain priority; missing measured values fall back through MediaInfo, media server and then Radarr/Sonarr. Metadata warnings compare the filename with MediaInfo when present, otherwise with the media server. A media-server value that differs while MediaInfo agrees with the filename is muted information. MediaInfo audio tracks supply audio, language and channel presentation. Source and processing retain filename/Arr behavior, and existing comparison equivalences remain available.
- **Rename directly on Unraid disks.** The video and each selected companion resolve independently to their physical devices, including companions on another disk or pool. Physical moves use no-replace rename operations rather than hardlinks or cross-device copies, and rollback reverses each file on its original device. Duplicate files block preview with a Disk placement instruction. Preview shows devices or the user-share fallback hint. After a completed service refresh, newly present folder devices produce a warning in the toast and log; Arr or a media server can have written NFO files or artwork through the user share.
- **Create custom tags while applying them.** Enter a new name in the single-file or selection dialog; it appears selected with a New marker. Apply creates it and assigns it together with the other changes, including selections spanning pages. Cancel creates nothing. Case-insensitive matching reuses existing names, and the 128-tag catalog limit is enforced before applying changes.
- **Keep a default file owner in Unraid settings.** Paths and Default owner cards sit above Shares. Existing file-check owner values carry forward; new defaults are 99:100. Opening or resetting Files & permissions uses those values, and scanning does not overwrite them. The process UID/GID remains visible; findings that it cannot fix remain Manual and are skipped by Fix all.
- **Simplify the event log.** Remove the unseen-error dot from Settings and Log and the Open job log link from event details. The ordinary event log, filters, details and export remain available. New metadata and mediainfo sources explain confirmations and explicit reads.

## Compatibility and rollback

Version 1.6.0 adds the `field_confirmations` and `mediainfo_results` tables without increasing the database schema version. Existing tables and recognition-rule definitions remain compatible. **Rollback to 1.5.1 is supported without restoring a database backup**: that version opens the database and ignores the new tables, settings and evidence fields. Confirmations and MediaInfo presentation are unavailable while running the older version; its own metadata resolution applies when it rebuilds the cache. Keep the complete Appdata directory and matching `secret.key` for either version.

MediaInfo results remain valid only while service instance, file ID, Arr path and size match. Missing or changed files invalidate results during synchronization. Scopearr renaming updates the saved result path, but an Arr replacement with a new file ID requires another read. Manual confirmations similarly stop applying when the file ID or size changes, or their source has no value.

MediaInfo is disabled until explicitly enabled and installed. Library exploration still needs no media mount. Existing mounts, credentials, presets, rules and tag assignments are retained; installations enabling inspection or physical renaming must add the appropriate mounts themselves. Image updates do not alter saved Unraid container paths or limits.

Retain the supported **512 MiB memory limit without additional swap** and `GOMEMLIMIT=64MiB`. See the [MediaInfo guide](../MEDIAINFO.md), [metadata evidence](../RECOGNITION.md), [Unraid guide](../UNRAID.md), [MKVToolNix and renaming](../MUX.md) and [validation report](../VALIDATION-1.6.0.md).
