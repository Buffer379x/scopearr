# Scopearr 1.4.4

Disk placement now reads the shares behind your Radarr/Sonarr root folders directly on the disks, tool pages stay calm after a scan, and a new 24-hour event log explains what happened in the background.

- Disk placement is share-first. Each Radarr/Sonarr root folder resolves to its share folder below `/unraid/user` (saved choice, path mapping with identity check, or a share of the same name), and every share is read once per disk. Only shares reported by enabled Radarr/Sonarr instances are scanned; unrelated shares such as photo libraries are never read. A root used by both Radarr and Sonarr, for example `/documentaries`, is scanned once for both. Folders on one disk appear as compact rows without a size; folders without an Arr entry are listed with **No Radarr/Sonarr entry** and have their own status filter.
- Disk placement no longer requires MKVToolNix or path mappings; mappings only help to resolve root folders. Files & permissions and physical mux output still use them.
- **Settings → Services → Unraid → Shares** lists the Arr root folders with their instances, the detected share folder and its status. Choose another share, a subfolder or **Do not scan** when the automatic match is wrong.
- The scan report's **Shares** table shows folders found on disks, on several disks and on one disk, folders without an Arr entry and Arr entries without a folder, plus the devices checked. Unresolved roots and empty shares are explained inside the report with **Open in settings**; a dot on the report icon marks notices.
- Disk placement and Files & permissions no longer show result-dependent boxes between the filters and the results. Scan errors appear once as a toast; notices move into the report.
- Dialogs close after a successful save. Tool pages share one vertical rhythm, the Scan button uses the standard control height and card headings align at one minimum height.
- **Settings → System** has **Info** and **Log** tabs. The log lists start-up, sign-ins, settings, syncs, tag sync, webhooks, media-server matching, mux jobs, disk placement, file fixes and renames from the last 24 hours, with search, level/source/service filters, sorting, details, repeat badges, text/JSON export and Clear. Credentials are redacted before storage. A red dot on the settings button marks new errors; sync, tag-sync and scan error toasts offer **Show in log**.

After updating, open **Disk placement → Scan report → Shares** and compare **On several disks** for a share with the Unraid host:

```bash
for d in /mnt/disk*/documentaries/*/; do basename "$d"; done | sort | uniq -d
```

## Compatibility and rollback

The new `event_log` table is additive; the schema version is unchanged and there are no dependency updates. Rollback to 1.4.3 has no restrictions; the log table is ignored. Run a new disk-placement scan after upgrading (and after a rollback) to replace the previous scan results. Retain the **512 MiB memory limit without additional swap**.
