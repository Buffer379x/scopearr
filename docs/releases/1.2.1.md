# Scopearr 1.2.1

Notifications now appear above native modal dialogs and their backdrops, stay readable and interactive, and retain their remaining display time when dialogs open or close. File details show mux API errors once through the notification instead of repeating them beside the button.

MKVToolNix can use a separate working directory. The default remains **Same folder as the media file**. Separate output is verified, then moved or copied across mounts into the media directory before replacement. Copies support cancellation, disk flush and size verification; job directories are cleaned on completion, failure, cancellation and restart. Both filesystems need source-size free space plus 1 GiB. Changing the directory waits for queued/running jobs to finish.

The Unraid template suggests an optional **Media root** (`/mnt/user/` → `/media`) and adds an optional `/mux-work` mount. Values remain empty until configured. **Existing containers must adopt mounts manually** by editing `/media` or using Add another Path. Root mounts expose all shares beneath them read-write; use appropriate mappings and permissions. A 512 MiB container limit remains recommended for MKVToolNix. See [the mux guide](../MUX.md).

Service tabs, disabled services and service choices are sorted alphabetically without changing saved instance order. MKVToolNix settings now match the other services, with separate tool/update, path mappings and processing sections. Tool polling slows down while idle. English, German, Spanish and Italian translations are included.

There is **no database migration**: schema 16 is unchanged. Rollback to 1.2.0 accepts and ignores the new `mux.workDir` JSON setting; 1.2.0 then uses its original same-folder behavior. Finish queued/running jobs before changing versions. Versioned amd64/arm64 images and the stable tag are published by the approved release workflow.
