# Scopearr 1.4.6

Disk placement can now consolidate cache files manually, remembers its last checks and explains the actual files that prevent a move. The Mux page gains the same bulk unmark action as the libraries.

- **Cache is an ordinary source device.** Files on cache and an array disk, or cache with an empty array folder, are Split and can be consolidated individually or through **Start all**. Targets are always eligible array disks. If no array disk has the folder, Scopearr chooses one by free space and identifies it as a new target. Files only on one pool remain On one disk.
- **Share policy remains authoritative.** Prefer/Only shares never move pool files onto the array. Mixed pool/array folders explain the restriction and have no target. The report shows each share's cache policy and one notice when `shares.ini` is unavailable. A running mover or parity operation still blocks execution and makes queued work wait. Legacy Mover results remain readable; their filter/report column disappears once its count is zero.
- **Checks survive closing and reloading.** The status dialog shows the last check's local time and concrete file details: disk, path, owner, permissions and reason. Unchanged scans retain it; changed files clear it. A saved blocker adds a small warning dot to the status badge. Successful moves retain the last preflight until the row is removed. Failed rechecks are retained too; diagnostics identify up to 50 distinct files within 16 KiB.
- **Different ownership alone no longer prevents a move.** Sources must be readable and removable by the Scopearr process; conflicts, special entries, unavailable targets and insufficient space remain blockers. Copies belong to 99:100 and retain mode and timestamps. The dialog warns about owner changes, the start confirmation counts them, and the log records them. A link opens Files & permissions with the folder search prefilled; that tool keeps its own configurable ownership rules. Recovery still verifies the source and the expected 99:100 copy before removing anything.
- **Remove mux marking from selected jobs.** The Mux page reuses the library component, including confirmation, sequential progress and one result toast. Running, queued and backed-up jobs are skipped and reported; this action never cancels them. Search, filter, sorting and page changes clear the selection; hidden jobs cannot be removed accidentally. A single removable marking needs no confirmation.

## Compatibility and update

`check_result` is an additive placement column; the SQLite schema version is unchanged. The 1.4.5 column lists can still read and write the database, with unrestricted rollback to 1.4.5. No dependencies were updated. **Run a new disk-placement scan after updating or rolling back.** Scans do not start automatically. Keep the **512 MiB memory limit without additional swap**.
