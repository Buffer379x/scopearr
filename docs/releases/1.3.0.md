# Scopearr 1.3.0

Enable the new Unraid service under Settings → Services and open **Disk placement** to find movie or series folders spread across physical disks. Scans read directory metadata only and run on demand. Choose libraries, group series by series or season folder, exclude target disks, reserve free space and optionally verify copies with SHA-256. The scan summary groups planned moves by target disk; click a target to filter, select its items or export CSV.

The planner consolidates onto an existing array disk, preferring the largest existing share of the item and accounting for free space reserved by earlier planned moves. Small companion-file moves appear separately from media-file moves. Pool/array mixtures wait for the mover; duplicate paths, changed files, foreign ownership and insufficient space require attention.

Start one item, a selection or all ready items. A single worker reports item and overall progress, supports cancellation and preserves completed copies. Copies stay hidden as exclusive `.partial` files until synchronized and verified; publishing never overwrites a file. Source files are removed only after verification. After a restart, unfinished copies are cleaned up, published copies are checked and interrupted items require another check before continuing. File modes and timestamps are retained; moving files requires UID 99/GID 100. Placement moves use physical disks only and keep user-share paths unchanged, so no Arr or media-server rescan is triggered. Mux and placement workers share a file-operation lock.

With **Write mux output to the original's disk**, mux output, temporary files and backups use the original's physical disk or pool. Multiple matching originals block the job; no physical match falls back to the existing user-share behavior with an explicit status and log message. An optional mux working directory remains supported.

Add the optional `/mnt/` → `/unraid` mount for physical disks and `/var/local/emhttp/` → `/unraid-state` read-only for mover/parity waiting. Existing containers need **Add another Path**; image updates do not add mounts. Never mount the Docker socket. See [Unraid setup](https://github.com/Buffer379x/scopearr/blob/v1.3.0/docs/UNRAID.md) and [mux behavior](https://github.com/Buffer379x/scopearr/blob/v1.3.0/docs/MUX.md).

SQLite upgrades from **schema 16 to 17 with an automatic backup before migration**. **Rollback to 1.2.6 requires restoring that pre-migration backup**, together with the existing Appdata secret key. The container budget remains **512 MiB**, with `GOMEMLIMIT=64MiB`. Placement copies synchronize at least every 16 MiB to bound dirty write-cache pressure observed on real Unraid.
